## Задание 1: почему такие коллекции

Сами книги лежат в списке, потому что это то, что реально меняется: книги
добавляются, удаляются, я по ним хожу в цикле, и порядок добавления хочется
сохранить. Одну книгу я сделал кортежем `(id, title, year)`: полей всегда ровно
три, менять их по одному мне негде, зато кортеж нельзя случайно испортить, а он
у меня лежит сразу в двух местах (в списке и в индексе). Индекс `id -> книга` —
это словарь, потому что поиск по id нужен чаще всего, и бегать ради него по
всему списку глупо. Жанры — множество: мне от них нужно только "есть такой жанр
или нет", дубликаты не нужны, порядок тоже.

Про ловушки с семинара. В конструкторе стоит `books=None`, а не `books=[]` —
иначе список создался бы один раз на все экземпляры. `all_books()` и `genres()`
отдают копии, чтобы наружу не уехала ссылка на мои же внутренние данные.
Ключи в словарях только int и str, списков в ключах нет. В `remove_older_than`
я не удаляю из списка во время прохода по нему, а собираю новый. Там, где нужна
независимая копия вложенной структуры, стоит `deepcopy`, а не обычный `copy`.

## Задание 2

`my_bug.py` — баг про hashable. Если у объекта `__hash__` считается по полю,
которое потом меняют, то после изменения ключ в словаре найти уже нельзя:
по старому значению не сходится `__eq__`, по новому — не та корзина. Причём
при переборе словаря он на месте, что и сбивает с толку. Починка — сделать
ключ неизменяемым (`@dataclass(frozen=True)`) и переименовывать через
`counters[new] = counters.pop(old)`.
