Задание 1: почему такие коллекции

Книги храню в списке. Их добавляют и удаляют, по ним надо проходить
циклом, и хочется помнить, в каком порядке они появились - список
для этого подходит лучше всего.

Одна книга - кортеж (id, title, year). Полей всегда три, по отдельности
я их не меняю, а кортеж нельзя случайно сломать. Это важно, потому что
одна и та же книга лежит и в списке, и в индексе.

Индекс id -> книга сделал словарём: искать по id приходится чаще всего,
и каждый раз перебирать весь список было бы долго.

Жанры - множество. Мне нужно только знать, есть такой жанр или нет.
Повторы не нужны, порядок тоже.

Ещё по ловушкам с семинара:
- в конструкторе books=None, а не books=[], иначе один список
  расшарился бы на все объекты;
- all_books() и genres() возвращают копии, чтобы снаружи нельзя было
  поменять мои данные;
- ключи в словарях только int и str, списков там нет;
- в remove_older_than не удаляю из списка пока иду по нему, а собираю
  новый;
- где нужна полная копия вложенной структуры - deepcopy, а не copy.


Задание 2

my_bug.py - баг с hashable-ключами. Если __hash__ объекта считается
по полю, а это поле потом меняют, то ключ в словаре больше не найти:
со старым значением не совпадает __eq__, с новым - хэш указывает не на
ту корзину. При этом если перебрать словарь, ключ там есть - из-за
этого баг и сложно заметить.

Починил так: сделал ключ неизменяемым через @dataclass(frozen=True),
а переименование делаю через counters[new] = counters.pop(old).
