# ДЗ к лекции 2 — трекер домашней библиотеки

Запуск: `python3 hw3/tracker.py` (задание 1) и `python3 hw3/my_bug.py` (задание 2).

## Почему такие коллекции (задание 1, `tracker.py`)

Набор книг хранится в **list**, потому что это единственная часть состояния, которая
постоянно меняется: записи добавляются, удаляются и обходятся по порядку, а список
дешёв на `append` и сохраняет порядок поступления. Одна книга — это **tuple**
`(id, title, year)` фиксированной структуры: полей ровно три, их состав не меняется,
а неизменяемость даёт бесплатную гарантию, что одна и та же запись, лежащая
одновременно в списке и в индексе, не будет испорчена через одну из ссылок.
Индекс `id -> запись` — **dict**, потому что поиск конкретной книги по ключу нужен
постоянно и должен стоить O(1), а не линейный проход по всему списку. Жанры — **set**,
так как там важен только факт наличия жанра без повторов и без порядка, и проверка
`in` тоже должна быть мгновенной.

## Ловушки семинара, которых код избегает

Изменяемых значений по умолчанию нет — в конструкторе стоит `books=None`, а список
создаётся внутри. `all_books()` и `genres()` отдают копии, поэтому наружу не утекает
алиас внутреннего состояния. Ключами словарей выступают только hashable-значения
(`int`, `str`), список ключом нигде не используется. Удаление по условию
(`remove_older_than`) не правит список во время прохода по нему, а пересобирает его
заново; для вложенных структур используется `copy.deepcopy`, а не поверхностный
`copy`/`dict.copy`.

## Задание 2 (`my_bug.py`)

Новый баг: объект-ключ с `__hash__`, посчитанным по изменяемому полю. После правки
поля ключ остаётся в словаре, но становится недостижим и по старому, и по новому
значению. Исправление — `@dataclass(frozen=True)` и явный перенос значения
`counters[new] = counters.pop(old)` вместо мутации ключа.
